Understand RAG by Running It

This simulator demonstrates the complete RAG pipeline. Follow each stage and observe what information moves from one component to the next.

1

Knowledge Base

External knowledge

RAG starts with external information such as PDFs, policies, websites, manuals or documents.

Important: The knowledge base itself is not RAG. It is the source from which RAG retrieves information.

UGRO Home Loan Policy
Eligible applicants must be between 21 and 65 years old.

Salaried applicants must provide salary slips and bank statements.

Applicants must provide valid identity documents.

Property ownership documents are required.
2

Chunking

Split information

Large documents are divided into smaller pieces called chunks.

Why?
Smaller pieces make retrieval more precise.

CHUNK 01
Eligible applicants must be between 21 and 65 years old.
CHUNK 02
Salaried applicants must provide salary slips and bank statements.
CHUNK 03
Applicants must provide valid identity documents.
CHUNK 04
Property ownership documents are required.
3

Embeddings

Text → numbers

Each chunk is converted into a numerical representation called an embedding.

Real embedding models can have hundreds or thousands of dimensions.

This simulator uses six dimensions so you can see the concept.

[0.80, 0.75, 0.40, 0.30, 0.20, 0.70]
CHUNK 03 VECTOR
[0.40, 0.30, 0.20, 0.85, 0.60, 0.50]
4

Vector Database

Searchable vectors

The embeddings are stored in a vector database.

The purpose is to make semantic search fast and efficient.

C1
Eligibility & identity documents
C2
Salary slips & bank statements
C3

Key Point

The vector database does not generate the answer.

It helps RAG find the right information.

5

User Query

Question → vector

The user asks a question.

The query is also converted into an embedding using an embedding model.

6

Similarity Search

Find relevant chunks

Now the query vector is compared with vectors stored in the vector database.

A similarity algorithm such as cosine similarity calculates how semantically close they are.

Chunk 2 — Salary Documents 92%
Chunk 1 — Eligibility 77%
Chunk 3 — Property 51%
Chunk 4 — Credit 34%
7

Context Augmentation

Build LLM context

The most relevant chunks are retrieved.

These chunks are combined with the user's question to create the context sent to the LLM.

8

LLM Generation

Context → Answer

The LLM receives the user's question together with the retrieved context.

It uses that context to generate a grounded answer.

FINAL ANSWER
For a salaried applicant, the required documents include:

• Salary slips
• Bank statements
• Valid identity documents
✓ Answer generated using retrieved knowledge-base context.

Why is this RAG?

The LLM does not need to have this specific policy stored in its training data.

RAG retrieves the relevant policy information and gives it to the LLM as context.

Your 10/10 RAG Mental Model

1. KNOWLEDGE Documents, PDFs, URLs, manuals, policies, FAQs etc.
2. CHUNKING Break large documents into smaller searchable pieces.
3. EMBEDDING Convert each chunk into a numerical representation of its meaning.
4. VECTOR DB Store embeddings so semantic search can find relevant information.
5. QUERY EMBEDDING Convert the user's question into a vector using the embedding model.
6. RETRIEVAL Compare query vector against stored vectors and retrieve Top-K chunks.
7. AUGMENTATION Combine the user's question with retrieved text as context.
8. GENERATION LLM uses the retrieved context to generate the final grounded answer.

The Most Important Formula

USER QUERY → QUERY EMBEDDING → RETRIEVE RELEVANT CHUNKS → QUERY + CONTEXT → LLM → ANSWER

Embeddings help retrieve the information. The retrieved text is what provides context to the LLM.
